L'onboarding est un parcours obligatoire de 6 étapes permanentes (Accueil, Anniversaire, Goûts, Souhaits, Amis, Ma Page), piloté par l'état réel des données en base. Il est contourné si le flag 'onboarding_completed' est à vrai dans le profil. Sinon, il s'ouvre à la première étape incomplète : date d'anniversaire (pré-remplie via les métadonnées d'inscription avec auto-fermeture du calendrier après sélection), goûts sélectionnés (persistés dans 'profiles.selected_tastes'), favoris ajoutés (≥3, filtrés par les goûts), ou cercle d'amis constitué (≥3 invitations validées ou membres dans le cercle). La 6ème étape ('Ma Page') exige la création de la page d'anniversaire, le lancement d'une cagnotte réelle (via le modal 'WishlistFundPickerModal' et validée par polling) et le partage social (≥3 actions). L'auto-redirection vers le dashboard ne se produit qu'après la validation de cette étape finale.

En complément du parcours bloquant, une entrée "Ma page d'anniversaire" (icône Cake, première position) du Sheet `+` (CreateActionMenu) ouvre `BirthdayPageBuilderModal` : une checklist 6 étapes accessible à tout moment, dans cet ordre **wishlist → type → friends → fund → publish → share** : (1) souhaits ≥3 dans `user_favorites` ; (2) type de page self/friend/other_event en localStorage `bp_type_${userId}` ; (3) **association d'amis à la page** via `BirthdayPageFriendsPicker` qui sélectionne des contacts (table `contacts`) et persiste localement (`bp_friends_${userId}`) puis dans la table `birthday_page_friends` (page_id, contact_id) une fois la page créée — note explicite affichée à l'utilisateur que les amis sélectionnés recevront des rappels WhatsApp J-7/J-3/J0 ; (4) cagnotte birthday active dans `collective_funds` ; (5) page publiée via `published_via_onboarding=true` (à la publication, les amis du localStorage sont insérés en batch dans `birthday_page_friends`) ; (6) partages ≥3 dans `onboarding_shares`. Le statut est calculé par `useBirthdayPageBuilderStatus` (useQuery key `['bp-builder', userId]`, staleTime 30s) et invalidé sur l'événement `feed-refresh`. L'étape 5 (publier) appelle la même logique que `handleCreateBirthdayPage` pour `self`, sinon redirige vers `/event/create?occasion=...`. L'étape 6 (partager) ouvre `BirthdayPageShareButton`. La page publiée est visible dans le fil d'actualités ET un mini-badge `Cake` rose sur l'avatar du profil utilisateur (hook `useMyBirthdayPageSlug`) permet d'y accéder à tout moment depuis `WhatDoYouWantCard`.
